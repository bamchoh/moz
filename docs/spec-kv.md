# KV ホストリンク実装仕様 (フェーズ 21: サーバ)

この文書は `Moz.Core/Kv/` の仕様であり、`tests/Moz.Tests/KvHostLinkTests.cs` (デバイス表記・ハンドラ・ランナー) と `KvConfigTests.cs` (設定) がこの内容をエンコードしている。両者を同時に更新すること。

moz はキーエンス KV シリーズ (KV-7500 / 8000 / 5500 / Nano 等) の **上位リンク (ホストリンク) 通信**を TCP (実機は 8501) で受ける **サーバ** (CPU ユニット側のシミュレート、`[[server]] protocol = "kv-hostlink"`) である。クライアントは未実装。設定は docs/spec-config.md。実機では未検証 (`?K` の応答コードなど、実機と違う点があれば仕様とテストを直す)。

## 行プロトコル

- 要求は ASCII 1 行 = 1 コマンド。終端は CR (CR LF と LF も受け付ける)。空行は無視する (応答なし)
- 応答は必ず CR LF 終端。コマンドとデバイス名の大文字小文字は区別しない
- 1 行が 4096 バイトを超えたら MalformedFrame ログを出して **無応答で接続を閉じる**。それ以外の行には必ず応答する (エラー応答を含む)
- 1 接続で要求は逐次。複数接続は同じ device を共有

| コマンド | 書式 | 正常応答 |
|---|---|---|
| 通信開始 / 終了 | `CR` / `CQ` | `CC` / `CF` |
| 機種 / モード | `?K` / `?M` | `55` (KV-7500 相当) / `1` (RUN) |
| 読出し | `RD <dev>[.fmt]` | 値 1 つ |
| 連続読出し | `RDS <dev>[.fmt] <count>` | 値を空白区切りで count 個 |
| 書込み | `WR <dev>[.fmt] <value>` | `OK` |
| 連続書込み | `WRS <dev>[.fmt] <count> <v1> ... <vN>` | `OK` |
| リレーのセット / リセット | `ST <relay>` / `RS <relay>` | `OK` |

未対応: `STS` / `RSS`、`RDE` / `WRE`、モニタ登録 (`MBS` / `MWS` 等)、コメント・プログラム系。すべて `E1`。

## デバイスと書式

| デバイス | 種別 | 番号 | 既定の割り当て |
|---|---|---|---|
| DM, EM, FM, W, ZF | ワード | 10 進ワード番号 | DM → words 0.. (全長)。他は `[[server.map]]` |
| R, MR, LR | ビット (リレー) | チャネル × 100 + ビット (00..15)。`R1015` = ch 10 bit 15 | R → bits 0.. (全長)。他は `[[server.map]]` |
| B | ビット | 16 進、1 チャネル 16 ビット。`B1F` = ch 1 bit 15 | `[[server.map]]` |

- リレーは `[[server.map]]` のビットテーブルへ `channel × 16 + bit` の位置に写す (R100 ↔ bits[16])。map の `count` はビット数
- 書式サフィックス (ワードデバイスのみ; リレーに付けると E0): `.U` 符号なし 16 ビット (省略時)、`.S` 符号付き 16、`.D` 符号なし 32、`.L` 符号付き 32、`.H` 16 進 4 桁 (応答は大文字 4 桁、要求は 1..4 桁)。32 ビットは下位ワードが先 (DM100 = 下位、DM101 = 上位)。`RDS` / `WRS` の count は値の個数 (`.D` / `.L` では 2 ワードずつ)
- count は 1..1000。値は 10 進 (符号は .S / .L のみ意味を持つが、範囲内なら受け付ける)、`.H` は 16 進。リレーの値は `0` / `1` だけ
- 応答の 10 進値はゼロ埋めしない (`RD DM0` → `0`)

## エラー応答

| 応答 | 意味 | 条件 |
|---|---|---|
| `E0` | デバイスエラー | 未知のデバイス、ビット 16 以上、リレーへの書式、未知の書式、割り当てのないデバイス、番号 (+ count) が割り当て範囲外、`ST` / `RS` をワードデバイスに |
| `E1` | コマンドエラー | 未知 / 未対応のコマンド、引数の過不足、count が 1..1000 でない、値が書式の範囲外 (U: 0..65535、S: -32768..32767、D: 0..4294967295、L: int32、H: 1..4 桁)、リレー値が 0/1 以外 |
| `E4` | 書込み禁止 | `read_only_bits` / `read_only_words` に写したデバイスへの `WR` / `WRS` / `ST` / `RS` |

検査の順序: コマンド (E1) → 引数の個数・count (E1) → デバイスと割り当て (E0) → 範囲 (E0) → 値 (E1) → 書込み禁止 (E4)。

検証ベクタ (words[100..102] = 5678h, 1234h, FFFFh; bits[16..19] = 1,0,1,1):

| 要求 | 応答 |
|---|---|
| `RD DM100` | `22136` |
| `RD DM102.S` | `-1` |
| `RD DM100.D` | `305419896` (12345678h) |
| `RD DM100.H` | `5678` |
| `RDS R100 4` | `1 0 1 1` |
| `WR DM100.L -2` | `OK` → words[100] = FFFEh, [101] = FFFFh |
| `WRS DM100.D 2 65536 1` | `OK` → words[100..103] = 0, 1, 1, 0 |
| `RD MR0` (map なし) | `E0` |

Request ログ: `conn=c1 op=read target=DM100 qty=3 result=ok` / `op=write` / `op=set` / `op=reset` / `op=ctrl target=CR`、エラーは `err=E0` 等。接続の accept/close/error は他の TCP サーバと同じイベント。`unit_ids` は無視される。

テスト: デバイス表記 (各デバイス・書式・不正表記)、制御コマンド、各書式の読み書き、連続読み書き、リレーのセット / リセット、全エラー条件、map の上書き、TCP ランナー (CR / CR LF 終端、ログ、長すぎる行の無応答クローズ)。クライアント側は手書きのソケットコード。
