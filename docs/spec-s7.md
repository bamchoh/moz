# Siemens S7 実装仕様 (フェーズ 22: サーバ)

この文書は `Moz.Core/S7/` の仕様であり、`tests/Moz.Tests/S7ServerTests.cs` (エリア・ハンドラ・ISO-on-TCP・ランナー) と `S7ConfigTests.cs` (設定) がこの内容をエンコードしている。両者を同時に更新すること。

moz は Siemens S7 の **S7comm (S7-300/400 のクラシックプロトコル、S7-1200/1500 も「最適化ブロックアクセス」無効の DB なら同じ)** を ISO-on-TCP (RFC 1006、実機はポート 102) で受ける **サーバ** (CPU 側のシミュレート、`[[server]] protocol = "s7"`) である。クライアントは未実装。設定は docs/spec-config.md。Snap7 / python-snap7 / libnodave 等のクライアントを想定し、実機・実クライアントでは未検証。

## メモリエリアと割り当て

S7 のメモリはバイト単位・ビッグエンディアン。moz は **ワードテーブル**に写し、バイト b はワード b/2 の上位 (b 偶数) / 下位 (b 奇数) バイト。MW10 = words[5]、MB11 = words[5] の下位バイト。

| エリア | コード | 設定の `device` | 既定の割り当て |
|---|---|---|---|
| DB n (データブロック) | 84 | `DB1`..`DB65535` | DB1 → words 0.. (全長)。他の DB は `[[server.map]]` |
| M (フラグ、メモリビット) | 83 | `M` | `[[server.map]]` |
| I (入力。`E` も可) | 81 | `I` / `E` | `[[server.map]]` (read_only_words が自然) |
| Q (出力。`A` も可) | 82 | `Q` / `A` | `[[server.map]]` |

- `[[server.map]]` の `kind` は `words` か `read_only_words`、`offset` / `count` はワード単位 (count ワード = 2 × count バイト)
- タイマ・カウンタ (1D / 1C)、周辺 I/O、ローカルデータは未対応 (項目エラー 06 / 0A)
- 奇数バイトのアクセス、ワードをまたぐバイト列、ビット (DBX10.3 等) すべて可。書込みはバイト範囲を含むワード列を読み、上書きして 1 回で書き戻す (端のワードは read-modify-write)
- ログ上の表記: `DB1.DBW10`、`DB1.DBB11`、`DB1.DBD4`、`DB1.DBX10.3`、`MW0`、`MB5`、`I0.0`、`QD2`

## ISO-on-TCP (`IsoTcp` / `S7TcpServer`)

- TPKT: `03 00` + 全長 (2)。全長は 7 以上 2048 以下。COTP: 長さ (1) + コード + ...
- COTP Connect Request (E0) には Connect Confirm (D0) を返す: 宛先参照 = クライアントの送信元参照、送信元参照 = 0001、クラス 0、パラメータ (TSAP、TPDU サイズ) はエコー。**TSAP (ラック / スロット) は検査しない** (どの値でも接続できる)
- データ TPDU (`02 F0 80`) のペイロードが S7 PDU。断片化 (EOT ビット 0) は未対応
- Connect 前のデータも処理する (実機より寛容)。不正な TPKT (バージョン ≠ 3、長さ範囲外)・不正な COTP・S7 のジョブ / ユーザデータでない PDU (プロトコル ID ≠ 32、長さ不整合、ack) は MalformedFrame ログを出して **無応答で接続を閉じる**。それ以外の COTP コード (切断要求等) は黙って閉じる
- 1 接続で要求は逐次、複数接続は同じ device を共有し、PDU 長の交渉は接続ごと

## S7 PDU

ヘッダ: `32` | ROSCTR (01 job / 03 ack_data / 07 userdata) | 0000 | PDU 参照 (2、エコー) | パラメータ長 (2) | データ長 (2) | [ack_data のみ: エラークラス + コード (2)]。

| ジョブ | 要求 | 応答 |
|---|---|---|
| Setup Communication (F0) | `F0 00` AMQ (2) AMQ (2) PDU 長 (2) | 同じ形で PDU 長 = min(要求, 960)。以後の応答長の上限 |
| Read Var (04) | `04` 項目数 + S7ANY 項目 × n | `04` 項目数 + 項目ごとに 戻り値 (1) トランスポート (1) 長さ (2、ビット) データ (+ 奇数長なら詰めバイト、最後の項目を除く) |
| Write Var (05) | `04`→`05`、項目 + データ (項目ごとに `00` トランスポート 長さ データ + 詰めバイト) | `05` 項目数 + 戻り値 × n |
| それ以外 (PLC 停止 29、ブロック一覧 等) | | ack_data、エラー 8104、パラメータは機能コードのみ |

S7ANY 項目 (12 バイト): `12 0A 10` | トランスポート | 個数 (2) | DB 番号 (2) | エリア | アドレス (3; バイトアドレス × 8 + ビット)。トランスポート: 1 BIT、2 BYTE、3 CHAR、4 WORD、5 INT、6 DWORD、7 DINT、8 REAL (6/7/8 は 4 バイト。値の解釈はしない)。応答のトランスポートは BIT → 03 (長さ = ビット数、1 ビット 1 バイト)、他 → 04 (長さ = バイト数 × 8)。書込みデータは 03 (1 ビット 1 バイト)、04 (ビット長)、09 (オクテット列、バイト長) を受け付ける。

項目の戻り値: `FF` 正常、`03` 書込み禁止 (read_only_words)、`05` 範囲外 (個数 0、ビット > 7、バイト範囲が割り当てを超える)、`06` 未対応のトランスポート (タイマ・カウンタ等)、`07` 書込みデータ長が項目と合わない、`0A` 未知のエリア / 割り当てのない DB。読出し応答が交渉済み PDU 長を超えるときは項目を返さず ack_data エラー 8500。パラメータが壊れている (項目数と長さの不一致、`12 0A 10` でない) ときも 8500。

ユーザデータ (ROSCTR 07) の SZL 読出し (パラメータ `00 01 12 04 11 44 01 seq`、データ `FF 09 0004 SZL-ID index`) に応答する:

| SZL-ID | 内容 |
|---|---|
| 0011 (モジュール識別) | 28 バイトレコード × 3 (index 0001 / 0006 / 0007)。MlfB `6ES7 315-2EH14-0AB0 `、BGTyp C000、Ausbg1 0001、Ausbe 0001 |
| 001C (コンポーネント識別) | 34 バイトレコード (index 1 システム名 `moz`、2 モジュール名 `CPU 315-2 PN/DP`、3 プラント `moz`、4 `Original Siemens Equipment`、5 シリアル `S C-MOZ0000001`、7 `CPU 315-2 PN/DP`、8 `MMC 0000000000`) |
| それ以外 | ユーザデータ応答でエラー 8104、データ `0A 00 0000` |

応答パラメータは `00 01 12 08 12 84 01 seq 00 00` + エラー (2)。SZL 以外のユーザデータ機能も 8104。

検証ベクタ (DB1 既定、words[5..6] = 1234h, 5678h):

| 内容 | PDU |
|---|---|
| DB1.DBW10 読出し | `32 01 0000 0100 000E 0000` + `04 01` + `12 0A 10 04 0001 0001 84 000050` → `32 03 0000 0100 0002 0006 0000` + `04 01` + `FF 04 0010 1234` |
| DB1.DBB11 2 バイト | 項目 `12 0A 10 02 0002 0001 84 000058` → `FF 04 0010 3456` |
| DB1.DBX10.3 | 項目 `12 0A 10 01 0001 0001 84 000053` → `FF 03 0001 01` (byte 10 = 08h のとき) |
| DB1.DBW10 ← ABCDh | `05 01` + 項目 + データ `00 04 0010 ABCD` → `05 01` + `FF` |

Request ログ: `conn=c1 op=read target=DB1.DBW10 qty=<項目数> result=ok` / `err=0A` (最初の項目エラー)、`op=write`、`op=setup target=pdu=480`、`op=szl target=0011`、`op=cmd=29 err=8104`。接続の accept/close/error は他の TCP サーバと同じイベント。`unit_ids` は無視される。

テスト: エリア表記、既定 map、Setup の交渉、各トランスポート・奇数バイト・ビットの読出し、複数項目 (詰めバイト・項目エラー)、バイト単位の範囲検査、PDU 長超過、書込み (ワード・奇数バイト・ビット・複数項目・オクテット列・各戻り値)、未対応機能、SZL 0011 / 001C / 未対応 ID、不正 PDU、TPKT / COTP の解析と組み立て、TCP ランナー (接続 → Setup → 読み書き、接続なしの処理、不正 TPKT の無応答クローズ)。クライアント側は手書きのソケットコード。
